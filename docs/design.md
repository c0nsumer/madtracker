# MadTracker design

MadTracker lets one person score a night of track cycling races. The scorer easily enters what happens; the program tabulates the results and points, generates the PDFs for the awards ceremony and the archive and the USAC-compatible CSV for upload, and, as the scorer enters the proceedings, a beautiful, easy to read scoreboard tells the audience what is happening. It does not time anything and it does not police rules.

This document is the design the program is built to. It describes what the scorer sees and does. It is written before the code, and when the two disagree, the code is wrong.

## 1. Who uses it and where

- **The scorer** is a volunteer, often older, who knows track racing. They sit at a laptop with a mouse and a headset radio. The officials call placings to them by name or bib. They are not a programmer and do not want to be.
- **The laptop** runs Windows, macOS, or Linux; the program must work equally well on all three, with the same screens, keys, and behavior, and be packaged for each. Linux is also where it is developed and tested headless.
- **The venue** has one laptop and TVs placed around the building, all fed the same picture from the laptop's HDMI output. The program needs to know nothing about that: it shows the scoreboard full screen on the second display, or on the display the scorer chooses, and the venue's video system does the rest. On the scoring window's own display (one display, or that display chosen) the scoreboard opens as an ordinary window instead, so it never covers the controls; it fills its display again once the scoring window moves off it. Riders and spectators read it from the stands.
- **The night** has one event with seven to eighteen races, fields of two to sixteen riders, Madisons of three to eight teams. Many riders ride three races. Everything is entered live, under time pressure, and corrected minutes later when an official changes a call.

## 2. What the program is for, and is not

MadTracker is for setting up a list of riders who compete in track cycling races that are part of an event at a venue, recording placings and points as those races happen, and producing the night's results. Some events are part of a series.

It is not a rule-tracking system. It implements the scoring arithmetic of the USAC rulebook, citing the UCI rules where they say the same, and lets a venue vary the point values. It does not enforce conduct rules, warnings, gear limits, or eligibility. It does not time races.

## 3. Words

One word per idea, used the same way on every screen, in the code, and in this document.

| Word | Meaning |
|---|---|
| Venue | The place. One data file holds one venue: its name, logo, riders, events, and rulesets. |
| Series | An optional name that groups events, such as a winter series. A label on the sheets, not what a multi-race standings sums. |
| Event | One date of racing at the venue. It has a roster and a program. |
| Roster | The riders entered in the event, each with a bib number for that event. |
| Rider | A person. Riders are kept from event to event. A rider record holds only what stays true about the person: name, USAC License, UCI ID, birth year, and whether they are still racing. |
| Group | A label on a roster entry, such as "A" or "Juniors", used to fill a race's field. |
| Program | The event's races, in order. |
| Race | One contest with one format and one field. |
| Field | The riders or teams in a race. |
| Team | Riders scored together. A team has a color and may have a name of up to 40 characters; without one, its color is its name. The color is only the default name, so any name is allowed, another team's color included. The format fixes how many: two in a Madison, three in a team sprint, four in a team pursuit (UCI 3.2.077, 3.2.144). |
| Format | How a race is scored. The race dialog offers two groups. First the USA Cycling Rulebook formats, each shown with its article: Elimination (miss-and-out), Handicap, Keirin Final, Madison, Points Race, Scratch Race (chase), Sprint Final and Tempo Race. Then the club formats a named venue's program describes: Chariot, Unknown Distance, and Win-and-Out. Handicap, Keirin Final, Sprint Final, Chariot, and Unknown Distance are scored as a Scratch Race is. Timed events (time trials, pursuits, team sprint, team pursuit) are scored by entered times in a later version; the data model allows them now. |
| Ruleset | The point values a venue scores with. |
| Result | Placings, and points where the format has them. A result is provisional until the scorer marks it final. |
| Standings | A points table over races from several events, such as a weekend's Team Omnium. Its kind says how it scores. |

In text, a bib is written #12 before the name; in a table it has its own column.

"Track cycling", not "velodrome". "Venue", not "facility". "Event", not "meet".

## 4. Principles

1. **One click does the obvious thing.** On every screen the main action is a click on the thing it applies to. There are no modes to switch into and no verbs to select before clicking.
2. **Say it once, on the control.** A screen states its task in one line at the top. Everything else is carried by labels, placement, and tooltips. No legends, no footers, no paragraphs.
3. **Nothing is silent.** Every click either changes something the scorer can see or says, in one line, why it did not. Every button darkens for a moment after a click, so a tap on a touchscreen is seen to land.
4. **Everything is saved as it happens.** Each entry is on disk before it is confirmed. There is no save, and nothing on screen talks about saving.
5. **Mistakes cost one click.** Undo is always visible and says what it will undo. A wrong placing is fixed by moving a row.
6. **The scoreboard shows what the scorer sees.** A preview of the TV is on the scorer's screen at all times.
7. **Large and plain.** Big type, generous targets, dark scoreboard, light operator window, one typeface, Material Design icons where an icon helps and nowhere else.
8. **No data entry practices carried over from other programs.** No typed grammars, no bib strings, no placeholders for riders nobody saw.

## 5. The window

One window, two columns and a bar along the bottom, always the same:

- **Left: the program, then the TV.** A pane the column's height, headed by the event's name with its date in gray under it ("No event" when none is open), then the races in order. Each row shows the race's name and group, and one word of status when it is not the obvious one: Racing (amber, a race with entries and no result yet: the one that asks before you switch away), Provisional, or Final, the words the surface, the scoreboard and the PDF use. The selected race is the one being scored. Selecting another race while one is still being scored asks first. Every action has a visible control, and nothing sits behind a right-click alone: a right-click (or a long press) on a card or a result row opens that card's or row's ⋯ menu, as a second way to it, and opens nothing anywhere else. The card or row whose menu is open stays lit, in the pressed tint, until the menu closes, so the menu says whose it is; a right-click on another card or row while a menu is open closes it and opens that one's (Qt alone kept the click that closed the menu). The races in the program light under the pointer as every other control does. Under the pane, the scoreboard preview in its own pane, with no heading and no label: the picture is the state. It is the TV's one control. A click on the logo puts the race up; a click on the race puts the logo back. Live is off, on the picture and in the Scoreboard menu, until the program has a race to show; a board left on Live goes back to the logo, and so does one when another event is opened, so the TV never shows a race the scorer did not choose. While the TV shows nothing (Scoreboard > None, or its display disconnected), the preview goes gray and faded under a monitor-off glyph and **Off** in gray ink, not red, since off is usually a choice, a click on it does nothing, and the menu's Logo and Live are grayed: a display picked in the list is the one way back, to what was behind the veil (section 10). No key hides the board.
- **Right: the surface.** What the scorer works on: the Edit Event screen before racing, the scoring surface for the selected race during it, the result after it.
- **The bar.** Under the columns, each control under what it governs. **Undo**'s label is one sentence, "Undo:" bold and the rest plain: what was done, who first, in the past tense, *Undo: Silver placed 4th*, *Undo: #7 Maya Petrakis gained a lap*, *Undo: #12 Tess Gallagher marked Did Not Finish*, *Undo: #7 Maya Petrakis moved up*, *Undo: Sprint 3 recorded*, *Undo: Finish recorded*; "Nothing to Undo" when the log is empty and "Reopen First to Undo" once the race is final (a rider's name in a lighter weight between two bold runs read as pieces, and the label says what was done, never that something was clicked or tapped). The **Edit** | **Score** switch, as wide as the program column, shows which of the two screens is open: **Edit** opens the Edit Event screen, and **Score** returns to scoring. It is the event's two screens, not part of the list. **Undo**, across the surface's width, names what it will undo; it is off while the Edit Event screen is open. Nothing else is in the bar.

The title bar reads the event, its date in parentheses, then the app: "Race Night 12 (2026-Oct-16) - MadTracker"; on macOS the event alone, "Race Night 12 (2026-Oct-16)", as Mac document windows are named, since the menu bar names the app, or the app's name alone with no event. There is no logbook pane: the log stays in the file, and every entry is replayed from it, but a pane of it was reassurance more than a thing to use. There is no Event pane: the program's heading and the title bar carry the event. Every pane, the columns, the bar, and the window's edge are one gap apart. The window opens maximized the first time on a laptop, and afterwards where it was when last quit. If that place is on a display no longer connected, it opens maximized again. The place is kept on the laptop, not in the data file.

Menus hold only what is rare: File (New Event, Open Event, Edit Riders; Export Program PDF, Export Results PDF, Export USAC CSV, Multi-Race Standings; Backup Now; Settings; New Data File, Open Data File; Quit, grouped by the job and ordered by how often, with the data files, rare and the most far-reaching, last), Scoreboard (one list of where the board goes: Automatic, each display marked Full Screen or Windowed, None for off; then Logo and Live, the same choice as the preview's click), Help (Getting Started, Scoring, Results, Multi-Race Standings, Backups; Demo Data File..., a sample data file to learn in; then Open Data Folder, which opens the open file's folder with its log and backups in the system's file manager; About). Nothing in a menu is the only way to do something a scorer does during a race. The keys are the platform's own, through Qt's standard key names, so the Mac shows Command where the others show Control: Undo (Z) is the Undo button, Close (W) closes the help and the dialogs that open as windows, Help is F1 and the Mac's Command-?, Settings takes the Mac's Command-comma, and Quit is Q. Nothing is on a bare key: a stray keypress must never score.

**Built-in help.** The Help items open one help window, rendered from Markdown pages kept for the scorer apart from the repository's documents (`madtracker/help/`, shipped with the program), with a contents list on the left. The pages are the scorer's, short, in the order a night needs them: Getting Started (the flow: the data file, Settings, the event, and its riders, the races, the scoring, the results, with only the basics of each), Scoring (how each format comes out, with its rulebook article or its club source), Results (the PDF and the USAC CSV), Multi-Race Standings (the four kinds, which teams, riders, and races count, the dialog, and the sheet), and Backups (when they're taken, and restoring one). A page's title is its heading and the text of every link to it. The window wears the main window's look: white panes on the gray body, a contents list with tall rows and the current page tinted, and the page laid out for reading: room on every side, lines held to about 80 characters however wide the window, taller lines, section headings in the accent color, and a paragraph that opens with Note, Suggestion, Caution, or Tip set in a tinted box. It is styled on the document Qt builds from the Markdown, so the pages stay plain Markdown and no web engine ships. The contents list has the pages, and under the open page its sections (its level-two headings), so a long page is a click from any part; the section being read stays selected as the page scrolls. A callout carries the app's icon for its kind (information for Note, a lightbulb for Suggestion and Tip, a warning for Caution), a table has thin lines, room in each cell, and a shaded header, and each page but the last ends with a link to the next, so the pages read in order. The pages link only to each other, since nothing else ships, and into each other's sections by GitHub's heading anchors, so one link works on GitHub and here. Above the columns, **Back** and **Forward** (a chevron each, square, and the platform's Back and Forward keys: Alt+Left and Alt+Right, Command-[ and Command-] on the Mac) step through the places visited, each at the scroll position the reader got to, as a browser does, since a link into a section is otherwise a one-way trip; a new place after a step back drops what was ahead. The rule register (`docs/scoring-rules.md`) is for officials and developers, and Installing (`docs/installing.md`) is for whoever sets up the laptop before the app can show its help; both stay in the repository. The screens stay uncluttered; the help is one keypress away: F1 opens the help for the screen in view (the Edit Event screen at Getting Started's The event, a race at its Scoring, the Multi-Race Standings dialog at Multi-Race Standings, and Getting Started from the top with no event).

## 6. Setting up an event

One screen, **Edit Event**, in three parts the scorer works through top to bottom.

**Event.** Name, date, series (a name picked from earlier events or typed). The series is a label and nothing more: it prints under the event's name on the program and the results sheet, and a multi-race standings picks its events by tick, never by this name. It stays: the venue's scorer uses it to mark the nights of a winter series, and that name on every sheet is what it is for. A new event can start from an earlier event's program: the same races, formats, rulesets, and sprint counts, with empty fields. A venue whose nights follow one shape sets up each night in one click. A check box under it, off until asked, also copies that event's roster with its bibs and groups, and each race's field and teams, for the second night of a two-day event; nothing else is copied.

**Roster.** A table of this event's riders: Bib, First, Last, Group, USAC License, and Age. The roster is a choice from the venue's riders, not a place riders come from. **Choose Riders...** opens the venue's riders with a box per rider, checked for those on the roster; checking a rider puts them on and unchecking takes them off, which is the only way off. It has no New, Edit, or Delete of its own: riders are added, imported, and kept in Edit Riders only (section 12), so a record is always made and changed the same way. With no riders yet it says *No riders yet*. Bibs are typed in place, and a group is picked in place from the event's groups, never typed, so a slip can't make a group of one. **Edit Groups...** lists the event's groups with their riders and races. New Group... makes one before anyone is in it, so the Group cells can offer it. Rename changes a group on its riders and on the races made from it, and renaming into another group's name merges the two: each unscored race made from either gains the other group's riders, and a rider taken out of it by hand stays out. A group a scored race ran under keeps its name, and one a race was made from is not deleted; each says so under its button. The BikeReg import is in Edit Riders and names the event whose roster it fills, the open one to start with, or no event. An import shows what it will do (new riders, matched riders, bibs, groups) before it does it. Each row has a status: New, New? (a rider with the same name is on file; unchecked), On file, Update (the file fills a blank on the rider), Review (the file and the rider on file disagree on a value) or Conflict (unchecked; Details says why). A blank is never a disagreement and is filled as it stands, and a name that differs only in case is no difference: the record keeps its capitals. On a USAC License or UCI ID match, a first name with the same first letter ("Mario" for Marius, "Nora M." for Nora) is no difference either: Details says "registered as Mario" and the record keeps its name, since the id says who it is and the name on file is the one in the results. Another first letter, a last name, an id, or a birth year is still a Review. A disagreement is never applied unchosen: Import first opens each checked Review row in the merge's value table, titled "Update <name> from the File (n of N)", and writes nothing until the last is settled; Cancel returns to the preview with the picks kept. When both the first and the last name differ, that window says "Both names differ: this may be another rider." above its table. Select All, Select New, and Select None set the Import checks for the whole file; a New? row and a row with a conflict stay off under the first two, since which record is right is decided a row at a time. A name match needs each id to agree or be blank on the row. A USAC License or UCI ID the rider on file has and the row lacks is a blank, so the match stands when both birth years are known and at most a year apart; the rider keeps the id. With either birth year unknown it leaves the row for the scorer, since a namesake junior with no license and a licensed parent would otherwise be one rider. A row that matches no rider by USAC License, UCI ID, or exact name, but looks like one (accents, hyphens or a middle initial aside, an initial, a shared birth year, or the first and last name swapped), offers that rider as a choice, named in Details ("may be ..."), and stays a new rider unless the scorer picks it. When that rider has the same name (accents, hyphens, or a middle initial aside), the row is New? and starts unchecked, since a checked default turned a renewed or blank license into a duplicate; picking New or checking it adds a new rider, picking "Same as" makes it that rider. A weaker likeness keeps the row New and checked; a USAC License or UCI ID on file for another rider unchecks the row and names who has it. So does an id the file gives to two people: the later row is a conflict, and checked anyway it adds a new rider without the id, never folded into the first. Two new rows with the same name note each other ("looks like row 7, ...") and stay checked, since twins exist. One rider's rows that give different groups or bibs note each other ("also registered as Masters 40+ (row 1)"), and the later rows start unchecked so the scorer picks tonight's. For a rider already on the roster the roster's bib and group stand, and Details says what the file has ("file says bib 20 (roster has 1)"). The preview's Group cell is the roster's picker, No Group first, then the event's groups and the file's; a typed name takes a listed group's spelling. A USAC License loses any leading zeros a spreadsheet added; a UCI ID keeps them. After Import, the Riders window shows the result line when a row was skipped or adjusted (an id held back), and says nothing after a clean import. Bibs come from the venue, which hands them out for each event; the scorer types them in the import preview or the roster table, and the program never assigns one. A rider may be on the roster without a bib, because the numbers often come after registration closes. An empty bib is tinted until it is typed, and the roster's count says how many are missing. A bib is unique within a race's field, not within the event: two riders who never share a race may wear one number. Checking a rider whose number is already in the field is refused with the name of who has it. A group that brings a clash fills the field anyway, and the race dialog names the clash. A race is scored only when every rider in its field has a bib and no two share one.

Riders age. A junior becomes a senior, a senior becomes a master, and a category upgrade can come any year, so the rider record carries no category, group or bib. Those are facts about one event and live on the roster entry: the BikeReg import fills the group from that event's registration category, and a rider added by hand gets the group they had at their most recent event as the suggestion, which the scorer can change. The bib is never suggested, since last event's number says nothing about tonight's. The birth year is kept on the rider because it never changes and it is what the season's age categories are derived from; the roster shows the racing age (age at the end of the year) next to the name as a hint when the group is picked, and enforces nothing.

**Program.** The races in order: name, format, group, sprints or places, field size, and the ruleset when the races use more than one. A race whose field holds riders from another group says so beside its field size, "12 riders, 1 from Juniors", in the race dialog and the program, so a rider racing out of their group is seen where the program is set up. This never reaches the scoreboard or the USAC CSV. Buttons: **Add...**, **Edit...**, **Duplicate...**, **Remove**, and an up and a down arrow (Move up and Move down, named in their tooltips). **Duplicate...** opens the race dialog, titled Duplicate Race, filled from the selected race: format, ruleset, sprints or places, group, field, teams, and USAC details. A typed name comes selected, so typing replaces it, and a default name stays the default. Saving makes a new race right after the original; nothing is made until then. A scored race duplicates too, since the copy is a new race and nothing in it is locked. Adding a race asks for its name, format, group (which fills the field), ruleset (the venue's default is selected), and the one number the format needs: sprints for a Points Race or Madison, places for a Win-and-Out. The sprints start blank, or at the count of the event's last race of that format, and the race is not saved until the count is set: a count saved unnoticed decides the race. A blank name saves as the group and the format, as the chosen ruleset names it ("Group A Devil" where the venue calls the Elimination that). A race also says whom it is for, Men, Women, or Mixed (Mixed unless chosen), which goes only into the USAC CSV. The race dialog has three boxes: on the left **Race** (name, format, sprints or places, group, ruleset) and under it **USAC CSV Details**, two fields to a row: **Gender**, **Category**, **Class**, and **Age group**, for the USAC CSV's Race Gender, Race Category, Race Class, and Race Age Group ("Cat 3/4", "Senior", "35+"). On the right, the whole height, **Field** (or **Teams**): a filter box over the roster as a list of checks, the field first, then the race's group, then everyone else, each part in bib order as the roster and the cards are, riders without a bib last by name. The filter follows the one rule every filter box in the program follows; Choose Riders, Edit Riders, and Merge Riders have the same box. Each typed word is matched anywhere in the first or last name, ignoring case, so "Maya P" and "akis" both find Maya Petrakis. Here a word also matches the group or the digits of a bib, and "#7" is bib 7 alone. Category, Class, and Age group are lists that also take typing: USAC's own words first (Category: Pro, Cat 1 to Cat 4, Novice, and Open, from rulebook 1D; Class: Youth, Junior, U23, Elite, Senior, Master, and Collegiate, from 1C1 and the template; Age group has no set list), then every value a race in the data file has used, so a value typed once is spelled the same every week. A Category that is only a race's group is not offered. When another race of the event has the same discipline, Category, Gender, Class, and Age group, a gray note under the box names it: USAC's template has no race name, so USAC may file the two as one (unverified until a real upload). It is a note and not a refusal, since the only way to set the races apart would be an invented value. A blank Category saves as the group, so every race has one. A new race starts with the Class and Age group of the group's most recent race in the event, else blank. The discipline code is not shown: it comes from the format. A scored race may still change these three, as it may change whom it is for. The field can then be adjusted rider by rider. Until the race is scored its field follows its group: a rider who joins the group later (checked onto the roster, imported, or given the group in the roster) joins the race, and a rider who leaves the group comes out of it. So a program copied from an earlier event fills as the roster is built, and a race with a group may be saved before anyone is in it. Races of other groups are left alone, so a rider added to one by hand stays. A team race's field is its teams, so its dialog shows the teams where the field would be: riders from the roster (the race's group first) grouped under a color, two for a Madison. Its field does not follow the group, since a rider who joins the group is on no team yet. A team may be given a name; otherwise the color is its name. A team is its riders. Before the first sprint is recorded, renaming a team, changing its color, or moving it in the Teams list keeps the clicks already made and their Undo. A team whose riders change is taken out and added again, so the race's staged clicks are cleared and Undo starts over. Deleting or merging away a rider does the same to the unscored races they were in, since the data file reuses ids and a kept click would name someone else. The Edit Event screen accepts larger teams for the timed team events (team sprint, team pursuit) that a later version scores by time.

While the screen is open, **Edit** is the filled side of the switch at the bottom of the program. **Score** is the way back, and returns to scoring on the race that was selected when Edit Event opened, or on the first race when none was. One corner holds the way in and the way out, and shows which screen is open. Setup can be reopened at any time. Once a race has any entry, only its name, whom it is for, and its three USAC fields can change: its format, group, ruleset, sprints or places, field, and teams are fixed, and the race dialog says *Scored races keep their rules.* An entry Undo took back is no entry. A race undone all the way to its start list is set up again like one never scored: its format, group, ruleset, sprints or places, field, and teams open in the race dialog, its field follows its group again, and Choose Riders and Edit Groups treat it as unscored. The undone entries stay in the file, so Remove still refuses it, with *Race 4 has had entries and cannot be removed.* (section 12).

## 7. Scoring a race

The surface for the selected race shows, top to bottom:

- The race's name, group, and format in one line, and at the right the field's size ("12 riders", "5 teams": the scorer's quick check that everyone is at the rail) and its state: Start list, Racing, Final sprint, Provisional, Final. Start list is gray, Racing and Final sprint amber, Provisional an outlined tag, and Final a filled green one: outlined while waiting to be confirmed, filled once final, on the surface, the program list, and the board alike. A race saved without a name shows its format as the title, with the group beside it and no format line repeating it.
- **The task line**: one sentence saying what a click does now.
- **The cards**: one large card per rider still in play, bib and name at the same prominence (a call over the radio may come as either, and the scorer must find the rider at a glance from either), sorted by bib; a team card shows its color and name on one line, its riders being listed in the standings beside the cards. The cards sit two to a row; a field with a rider's name too long for two columns takes one column of wider cards, the way a field of team cards sizes to its longest team name, so a name is never cut. A click on a card does the task. Each card has an actions button, a **⋯** strip along its right edge. It opens the actions on that rider: Did Not Start (while nothing is recorded or staged for that rider, whatever the rest of the field has done), Did Not Finish, Disqualify, and in the final sprint of a Points Race, Madison or Tempo Race, Out of the Finish (Mishap) for a rider not yet placed in it, and Withdrawn, in a race placed at the line, a Points Race, a Madison, or a Tempo Race, for a rider without a place in the sprint or finish being clicked: the card leaves, and the rider ranks after every rider still racing, the latest withdrawn highest (USAC 2O3(e), 1M6(d)). These ask first. A later status replaces an earlier one: a rider already marked Did Not Start or Did Not Finish can still be disqualified after a protest, from the result row's ⋯, and Undo puts the earlier mark back; the same mark twice is refused. While a sprint is being clicked, the card of a rider placed after another offers Tie with the Rider Above (Tie with the Team Above in a Madison), and the card placed before offers Tie with the Rider Below, after the moves; either records the one tie at once. Where laps count, the card also has **−1** and **+1** buttons beside the ⋯, side by side, for Lost a Lap and Gained a Lap; they record at once and do not ask, because a lap is routine and Undo is one click. Everything tapped on the touchscreen is at least a finger's size, 44 pixels: each lap button is 48 wide and the card's height, the ⋯ strip 44 wide, a result row 44 tall, and a ⋯ menu's items 44 tall. At 1366 that gives two columns of cards, and the standings give up rows, down to three, before a card scrolls out of view. A rider's net laps show as a chip on the card (+1 lap), so a lap taken before the finish is visible before the rider has a row in the result.
- **The result so far**: the placings or standings as they stand, in a table with alternating rows and no selection, updating on every click. A Madison row's Riders cell lists the team's riders one per line, with no divider between them; a long team name wraps in the Team column rather than taking the riders' room.

From 1300 px of surface width (a 1920 display) the cards and the result sit side by side: the cards on the left with 60 percent of the width, the result on the right. The cards grow into their column, up to 24 pt, never dropping a column of whole names and never cutting a team's name. Record Sprint is the cards column's full width and 60 px tall, the one button every sprint ends on. The result takes the width its columns need before the cards take their share, so every sprint column stays in view: the scorer checks each sprint by eye, and a table that scrolls sideways hides some. A name the result would cut takes back the cards' room past what their names want at the base size, so a long name that holds the cards to one column never leaves the result's names cut beside empty card space. A complete result with no cards gives the result the whole width. Below 1300 px (a 1366 laptop) the cards sit over the result, as before, and share the height with it.

There are no other buttons on the surface except where a format needs one, named below. A late rider is put in a race from Edit Event (section 6): Choose Riders for the roster, Edit Race for the field.

A race whose field holds a rider without a bib, or one bib twice, can't be scored yet. Its task line says why and where to fix it: *3 riders have no bib. Edit Event > Roster.* or *Bib 12 is worn by two riders in this race. Edit Event > Roster.* A click on a card repeats that line, and Record Sprint is off with the same reason. A rider without a bib shows an empty plate on their card, so the scorer sees who lacks one. Once the bibs are typed, the race scores as usual.

### Scratch Race

Task line: *Click riders in the order they finish.* Each click gives the next place and moves the card into the result. When every rider is placed, the result is complete and the race is provisional. A tie: in the result, the row's ⋯ offers *Tie with the Rider Above*, and the row above it *Tie with the Rider Below*: one tie, recorded from whichever row the officials named. While the order is being built, a staged row's ⋯ also offers *Move Up* and *Move Down* among the places clicked from the front, and *Move to Place* once three or more places are clicked from the front. A row placed from the back moves among the back's places, where up is the better place. Each move is one staged action with its own Undo. The last places are often known before the bunch is sorted (a dropped rider, lapped riders): the card's ⋯ offers *Place Last*, which gives the rider the last open place from the back, numbered from the riders left in the race, and moves the card into the result at the bottom. The order completes when the places clicked from the front meet those placed from the back. When the officials can't separate the middle, **Place the Rest Together** completes the order with every unplaced rider sharing the next place as an equal placing (USAC 1M6(a)). It sits in Record Sprint's slot and shows once someone is placed and two or more are not. The result is a tied group, as a dead heat is; no reason is recorded (only points are tracked). Undo takes back one mark at a time, from either end, and Undo of that finish brings both ends back as they were.

### Elimination

Task line: *Click the rider who is out.* Each click moves the card to the result from the bottom up. When two remain the line reads *Click the winner*; that click completes the result. If the ruleset keeps more than two riders for a final sprint, the line reads *Final sprint: click riders in the order they finish.* when that many remain. Two riders out at one bell are two clicks, then *Tie with the Rider Below* on the upper row or *Tie with the Rider Above* on the lower: the second click takes the better place and sits above the first, and either row records the one tie. The outs already in the result keep their ⋯ while the race runs: a rider the scorer missed is clicked out when noticed and moved to where they belong with *Move Up*, *Move Down*, or *Move to Place*, and the eliminations are renumbered to match.

### Points Race and Madison

The surface shows **Sprint 1** large in the task line, with how many places the sprint awards from the race's ruleset: *Sprint 1: click the first 4 riders in order, then Record Sprint.* (*click the winner* for a Tempo Race). A click past the scoring places is allowed, not refused, since a dead heat for the last place that scores is entered by clicking one more rider and tying them up; its badge is gray, with a tooltip saying it scores nothing. A reopened sprint's line says *Correcting Sprint 2:* with the same count. Clicks give places 1, 2, 3... as badges on the cards; a second click removes one. A badged card's ⋯ starts with *Move Up*, *Move Down*, and *Move to Place* (a submenu of the other places, shown with three or more places taken), so a wrong order is fixed in one move instead of by unclicking back to the slip and clicking everyone after it again. On a shared badge *Move Up* reads *Break Tie*, as it does on a tied row. Each move is one staged action, and Undo reads *Undo: #7 Maya Petrakis moved up*. **Record Sprint** is the one button, enabled once a rider is placed; it writes the sprint and the task line moves to Sprint 2. With fewer riders placed than the sprint awards (or than are left in the race), it asks first, Cancel the default: that is nearly always an early tap, but the judges do sometimes call fewer, so it is a question and not a lock. The last sprint reads *Final sprint: click every rider in order*; it completes on the last click, since the finish needs everyone. A rider whose mishap free laps run into the last kilometer can't return (USAC 2M7(b), 2M8(a)). During the final sprint the card's ⋯ offers *Out of the Finish (Mishap)*: the card leaves, the finish completes without them, and they are placed on the points and laps held, with "Out of the finish (mishap)" beside the name in the result. A rider the officials pull, or classify as though pulled, is marked *Withdrawn* from the card's ⋯ at that moment (USAC 2O3(e), 1M6(d)): the card leaves, no later sprint places them, and they rank after every rider still racing, the latest withdrawn highest, with the points and laps held as figures and "Withdrawn" beside the name. The task line of a Points Race, Madison, or Tempo Race has its own ⋯ at its right end from the race's first screen to its final one, so the line keeps one height as the race goes and nothing under it shifts when the first sprint is recorded; an item the race cannot take now is grayed, with why as its tooltip (nothing stands before the first recorded sprint, a correction is open, the final sprint has begun, the race is complete), never left out. In a Points Race or Madison its first item, the final sprint included, is *End Race Now, Result As-Is...*, for a race the officials stop after 80 percent and do not restart (USAC 2M6, 2N5: "Let results stand"). It asks first, *End the race now? Results will be recorded as-is.*, with Cancel the default. The race is then complete on the sprints ridden: nothing doubles, there is no final-sprint place, riders level on points share the place, and the table shows only the sprints ridden. The task line and the sheet's gray line say *Race ended after 3 sprints*, and Undo reopens the race. A Tempo Race has no such item, since USAC 2P5 restarts or reruns it. Under it is *Shorten Race...*, in all three formats until the final sprint begins, for a race the Chief Referee shortens (USAC 1G4(b)). It opens a box, *Shorten the race to how many sprints?*, with a number from the next sprint up to one below the count and the verb *Shorten*. Cancel is the default button, and Enter in the number records. The race rides on: the last sprint under the new count is the final sprint, doubled in a Points Race or Madison (USAC 2M2(f)), and the task line turns to it at once, with clicks already staged in that sprint kept as the first places of the finish. The sheet's rules line, the table, and the board show the count ridden, the gray line says *race shortened from 4 to 3 sprints*, and Undo (*Undo: race shortened to 3 sprints*) takes the latest shortening back; a second shortening lowers the count again. A count at or below the sprints ridden is refused, since that race stopped, and so is one at or above the count. The standings table shows the sprint columns and totals and updates as each sprint is recorded. Laps gained and lost are the card's +1 and −1. The card's ⋯ also offers the officials' two rulings. *Points Penalty...* shows the rider's penalty in points as it stands and sets it to the number the officials now say (USAC 8D5(b), "loss of points"; the glossary's relegation is "a loss of position, points or time"): the result has one Penalty figure per rider, so that is the number the scorer keeps, and a second ruling, a reversal, or a wrong rider is one dialog each; 0 takes the penalty off and the Penalty column empties (adding and removing entries cost three steps for two rulings and a reversal). The log keeps each change as the difference, so one Undo puts the earlier number back without touching the sprints recorded since. No reason is recorded: the app keeps score, the officials' sheet keeps the why. *Lap Not Counted* takes back a lap gained as if it had never been recorded, with its points (USAC 8D5(b) "laps illegally gained", 8D5(c) and 2N3(e) for a Madison relay without a touch); it is offered while a lap gained stands, and differs from −1, which is a second event on the track. The struck lap leaves no figure on the row, so the row carries "Lap not counted" beside the name (the sheet prints it, the table shows it as the row's tip), as a mishap out of the finish does. Both record beside the staged clicks, never instead of them. A penalty shows as a Penalty column in the standings, between Laps and Total, only while some row has one. A row's ⋯ is a strip the row's full height and a finger wide, as the card's lap buttons are, with the card's glyph. While the race runs each row of the standings has a ⋯ offering what the rider's card offers, less the staged moves and ties, which stay with the badge: the scorer who sees the wrong figure beside a name acts there, through the same questions and dialog. In a race scored by finish order the rows are the riders already placed, whose cards left with the click; after the row's moves they offer a lap where laps count, *Lap Not Counted* while a lap gained stands, and *Disqualify*, never a status, since a placed rider has finished. A Madison works the same with team cards: a click on the team's card is a click on the team, and the task line says *click teams in order*.

### Win-and-Out

Task line: *Lap 1: click the winner.* Each click awards the next place and moves the card out. After the last place the line reads *Click the rest in the order they finish*, and the result completes on the last click. A dead heat on a bell lap is an equal placing like any other (USAC 1M6(a)): both riders take the place, the next place is skipped, the next bell is for the next open place, and the race rings one bell fewer. The officials usually name one rider, and a dead heat for 1st is re-ridden, so the tie records what they called (the research is in `docs/research/win-and-out-dead-heat.md`). While a race in the reverse (Belgian) order runs, a rider marked Did Not Finish is listed after the highest place a lap has decided, never at a place a rider still holds.

## 8. Reviewing and finishing a race

When a result is complete the surface shows it as a list, the cards gone, with the state Provisional at the top right and **Mark Final** as the one button. Side by side (section 7), Mark Final and Reopen sit under the table they close, and the table has the whole width; stacked, they sit in the button row under the cards. The task line reads *Check the result, then Mark Final.* Each row has a ⋯ with *Move Up*, *Move Down*, *Move to Place* (a submenu of the other places, for a long move in one step), *Tie with the Rider Above*, *Tie with the Rider Below*, and *Disqualify*; on a tied row *Move Up* reads *Break Tie*, since it takes the rider out of the tie ahead of the rest and passes nobody (the first row of the tie too). Moving a row is how a wrong call is fixed, a relegation included. Where laps count, a row moves only among the riders on its lap, and *Move to Place* names only those places: the ranking puts a lap up ahead of the line, so a move across laps could not give the place it promised. In a Points Race, Madison, or Tempo Race the rows do not move, since the total ranks them; each row's ⋯ offers *Points Penalty...* and, while a lap gained stands, *Lap Not Counted* before *Disqualify* (section 7), because a ruling usually comes with the result in hand, after a protest. A Scratch Race row with a lap gained offers *Lap Not Counted* too. Either keeps the result Provisional. Elimination places decided by a bell move the same way, and moving one renumbers the eliminations; Undo takes a move back. Moving a Win-and-Out lap winner swaps the winners of two laps. For a Points Race, Madison, or Tempo Race the sprint columns are shown and a click on a sprint's column header reopens that sprint for correction, exactly as it was scored. The task line reads *Correcting Sprint 2: click riders in order, then Record Sprint.* The badges move as a live sprint's do (*Move Up*, *Move Down*, *Move to Place*, and *Break Tie* on the card's ⋯), and Record Sprint records the moved order. Record Sprint confirms; **Cancel**, to its left, leaves the sprint as it was. A recorded sprint reopens the same way while the race is still running, since a wrong sprint is often noticed a sprint or two later; the places already clicked for the sprint in progress come back once the correction is recorded or cancelled. Selecting another race or opening Edit Event cancels the correction too. A recorded finish order is corrected with the rows' moves, never reopened whole.

**Mark Final** fixes the result; the state reads Final, the task line reads *Marked final. Reopen to correct.*, and the only button is **Reopen**. Undo works until a race is final.

The scoreboard shows the result, labeled Provisional or Final, until the scorer selects the next race.

## 8a. Multi-race standings

The venue's omnium is a weekend: two events, each with its Madisons, and one set of standings at the end that sums them. A race's result belongs to its event, so standings that span two events cannot live in either one (the per-event omnium left in 0.1.26 for that reason). A **standings** is the scorer's definition of them, kept in the data file: a name, a kind, the events it covers, and the races left out. It is never stored as numbers. Each time it is shown or printed, every counting race is replayed from its log and the results summed, so a standings can never disagree with the race sheets it is built from.

There are four kinds, each ranking every group on its own by the total with ties by USAC 2B19(e). Two are for teams, over the Madisons of the ticked events. The **Team Omnium by Points**, as the venue's scorer keeps it on the sheet, sums each team's Madison totals as printed, negative and all. The **Team Omnium by Place** gives each team points for its place in each Madison from the **Place points** table and sums those, the omnium scoring of USAC 2B19(e) and the USAC glossary "OMNIUM"; the 2025 book leaves the points to the race announcement, so the table starts at the older book's 7-5-3-2-1 (USAC16 2O1), and a team past the end of the Place points table scores nothing. Two are for riders, over the races of the ticked events other than the Madison, whose entrants are teams (a Madison never counts in a rider omnium); the Four-Race Omnium counts only its four formats. The **Omnium by Place** gives each rider points for their place in each race from the same Place points table and sums those, as the club omniums surveyed in `docs/research/omnium-practices.md` do; every rider who rode any counting race is in the standings and a race not ridden adds nothing, with no minimum, no weight on the last race, and no attendance points (a minimum, if it ever comes, is one checkbox, "Only riders who rode every race"). The **Four-Race Omnium** is the omnium of USAC 2O1 to 2O3 (UCI 3.2.247 to 3.2.252): one Scratch Race, Tempo Race, Elimination, and Points Race per event, the first three scored 40-38-36 down to 2 and 1 from 21st, the Points Race's own points added, ties by its final sprint (USAC 2O3(g)), and a rider who does not start, does not finish, or is disqualified in any of the four out of the omnium and listed after every finisher as DNF or DQ; its points are the rulebook's, so it has no Place points row; the columns run in the order the omnium is ridden whatever the program's; and a ticked set short of a format or with one doubled, per event and group, is refused where the standings would be, never guessed: the rule as the red line ("A Four-Race Omnium needs one Scratch Race, one Tempo Race, one Elimination, and one Points Race for every group on each event."), then each ticked event short of it as a bold heading ("Race Night 13 (2026-Oct-18)") over one plain line per group in program order ("Group B: no Elimination", "Pro: no Tempo Race, 2 Eliminations, no Points Race"), the Standings box and the sheet alike; identical lines are not collapsed, since the scorer fixes the program one group at a time. The one race that may be left out is a group's Points Race (USAC 2O4: when it can't be run, or is stopped under 80 percent and can't be restarted, the standings after the Elimination are the final classification): unticked, the three races stand, Final once each is, and a tie with no final sprint to go to shares the place (1M6(a)); a program with no Points Race at all is still refused, so a forgotten race never makes a three-race omnium final on its own. The two-laps-down deduction (USAC 2O3(e)) is an **Omnium Penalty...** on the standings, one number per rider as a race's penalty is, taken off the total before ranking and shown in a Penalty column beside the total only when one is set, as the results sheet does; it is never a Points Penalty on the Points Race, which would change that race's own result. Only a ranked row's penalty brings the column in and only ranked riders are offered, once each in bib order; a change of kind takes the penalties off with the kind's other values; a rider in two groups' standings carries the one penalty in each. The button sits under the Standings box beside Export PDF..., for the Four-Race Omnium only (the other kinds have no article for one), and opens a dialog asking the rider (from the standings, "#12 Maya Petrakis") and the points, recording on Enter as the Points Penalty dialog does, 0 taking it off; the Standings box's rows stay read-only. A ticked event with none of the four is refused too, by name, its one line "No Scratch Race, Tempo Race, Elimination, or Points Race". A race still running is a column in a place kind once it ranks every rider still in it (a Points Race by points held), and waits, "(racing)" in the list and "Still racing" on the sheet, while it has riders unplaced (an Elimination half run would rank the riders out above the riders in); the Team Omnium by Points sums a running Madison as it stands. A DNF the race placed (an Elimination's, R-ELIM-7) scores that place. The names are unqualified "Omnium" for riders, as every results board reads, and the team kinds carry the qualifier; "Four-Race Omnium" names what the venue runs rather than an article number. Every race the kind counts in the ticked events counts unless the scorer leaves it out; a race keeps its own group, so a mixed-group race is ranked on its own rather than being guessed into one. A team is its pair of riders: the colors repeat and change between weekends, so the same two riders are the same team on every night, shown under the name and color they raced under last, and a pair that changes a rider is another team; a rider is the same rider by id, shown under the bib they raced under last. A team that rode fewer than every counting Madison of its group is left out of the standings, as the venue's sheet left out a team that rode one night of two; a team that started and did not finish rode, and one marked DNS did not. A race still to run is no column yet. A race whose result is complete is a column even when one rider is left in it and the rest are marked Did Not Start: that rider takes 1st and scores it, an Elimination's lone rider included. The standings wear one tag, Final, once every counting race is final and none is left to race, and none before: a season's standings would otherwise read Provisional for months, a warning that says nothing the count line does not, and no club posts a season that way.

There is one door: **File** > **Multi-Race Standings...**, after the night's exports, since it is an end-of-night job that is also a season's. The dialog has three columns: the file's standings on the left, the selected standings' page beside them, and the Standings box. On the left, the file's standings by name, with **Add...**, **Duplicate...**, and **Delete** under them (Delete, as in Rulesets: a standings is a thing of its own in the file). Beside them, the selected one's page: **Name**, **Kind** (a list of the four kinds; changing it saves at once and starts the standings from the new kind's defaults), **Place points** under it for the Team Omnium by Place and the Omnium by Place only (the table as "7, 5, 3, 2, 1", saved when the field is left; anything but whole numbers from 0 to 999 is refused on the red line and the old table put back; hidden, not grayed, for the other kinds), **Events** (a tick list of the file's events, newest first, with their dates), and **Races** (the races the kind counts in the ticked events under their event, all ticked; untick one to leave it out; a ticked one still in setup reads "(not yet raced)" in gray after its name; and with none, one gray line says so, "No Madison in the ticked events" or "No race in the ticked events"). The **Standings** box fills the rest: how many Madisons or races count over how many events (the Kind row already names the kind) and the Final tag once the standings are final, over each group's standings (a group with no label is headed No Group), as the PDF shows them, with the place, the team with its color and riders or the rider's bib and name, a column per race headed by its date ("Oct-17") and name, and the total (a Madison's cell is its total for the Team Omnium and its place points for the Team Omnium by Place; a rider's is the place points, or the Points Race's own points in the Four-Race Omnium), or the Four-Race Omnium's refusal on the red line where the standings would be. A long team name wraps, as on the sheet; a rider's name is one line, cut. A status row (a rider out of the Four-Race Omnium) shows no figures, as the sheet prints none. A refusal of what was typed survives the click that moved the selection, so it can be read. A group label with no spaces is cut, never scrolling the Standings box. The Place points table takes up to 50 places, the Rulesets editor's cap, so a table shown back is never cut by the field and saved short. The standings are computed again on every tick and every change of kind or Place points. The list and the page give way to the Standings box on a narrow screen, and in the table the riders give way first, then the race names are cut, then the riders go, and only then do the race columns scroll sideways between the team and the total, which stay in view (at 1366 by 768 the Total of three Madisons would otherwise be off the edge); a rider kind's names never go, since standings of bibs alone say nothing, so its races scroll instead. **Export PDF...** under it writes the sheet; the name goes from the latest event's date to the standings ("2026-10-18 - Oktoberfest 2 Day Omnium - Standings.pdf"), and the sheet shares the results' header with the band "Standings", with a FINAL tag once final and no tag before. On the sheet the name column never gives way past 40 mm: past what fits beside it, the standings print again for each run of races that does ("Races 1 to 8 of 20" under the group's heading), every band with the place, the name, and the total, so a season stays readable. Every change is saved as it is made, and nothing on the dialog scores a race, so it has no Undo and writes nothing to a race's log. There is no scoreboard page and no CSV: USAC takes race results, not standings.

## 9. After the night

File > Export Program PDF writes the program, posted for the riders to find their races and read by the announcer before each race to call its riders onto the track: no start times, since the night's pace sets those. The races in order, each with its group beside its name, its format and how it scores in a rider's words ("3 sprints, 10-7-5-3-2-1, double points for the last sprint"), a count at the right, and every rider in it by bib and name, in bib order, down then across three columns, whatever group they come from. A Madison lists its teams, color, name, and both riders. A race is kept on one page when it fits. The footer says when it was printed, since fields can change. The File menu also has two results exports, because PDFs are wanted through the night but the USAC CSV is uploaded once at the end. File > Export Results PDF writes the PDF for the awards ceremony and the archive. It asks for the whole event, or for a race picked from a list of the races that have started (the races the whole event prints), showing the selected race. The race is the default once it has started; otherwise the whole event is, and the list shows the nearest started race before the selected one. With no race started, the race choice is off. File > Export USAC CSV writes the USAC CSV for upload, in the ten columns of USAC's 2024 template and nothing else. The message after writing shows each race in a table with its discipline, category, class, and gender, so the scorer sees what USAC gets before uploading. Under it are the races left out because they are not finished, then what to fix before uploading (a blank category, a short field, races USAC may take for one, riders with no USAC License). The message has a Copy button left of OK that puts it on the clipboard as plain text, the races tab-separated, since its notes are wanted after it closes. Export Results PDF says nothing after writing: the scorer chose the place. Each asks where to save, in Documents by default, or in the exports folder when Settings names one. An export written over an earlier file is written beside it and swapped in once complete, so a write that fails partway, on a full or pulled USB stick, leaves the earlier file whole and no half-written file behind. The USAC CSV's columns were checked one by one against USAC's own template and the race dialog's USAC CSV Details box, and a venue's two-day file went through the upload, so nothing in the file changes without a reason from USAC's side. The suggested name goes from most general to least: the date, the event, the document, then the part ("2026-10-10 - Race Night 12 - Results - Overall.pdf", "... - Results - Points A.pdf", "... - Results - USAC Upload.csv"). The PDF is what the announcer reads from at the podium and what the officials check, so it lists each race's placings large and in order, with the points where there are any, and for a Points Race, Madison, or Tempo Race each sprint's points in its own column between the name and Laps, headed S1, S2, and so on, so the total's working is on the sheet as on the venue's own; a sprint in which a rider scored nothing is blank; the last sprint's figures are the points as scored, doubled where the rules double them, so the sprint columns, the laps at the gray line's lap value, and the penalty add up to the total, and those print at the sprint figures' size so the total alone is the row's; a race with more sprints than fit beside a readable name column prints one Sprints column with the sum. Names wrap rather than being cut. The results sheet and the standings sheet set their tables alike: the same place, bib, penalty, and total columns, and a name wraps up to three lines before its last line is cut, a hyphenated name breaking after its hyphen. A rider's name is bold on the podium rows and regular below them. The Total column is as wide as the table's widest total, and a standings race column as wide as its widest race figure, so one three-digit total widens only the Total. Every sheet, the program included, is the page a printer gives back: nothing prints within 10 mm of an edge, the black band included, since an office printer leaves up to 6.35 mm at each edge unprinted. The band is a block inside the margins, as wide as the table under it, 22 mm tall on the first page and 10 mm on the pages after, so a sheet printed at Actual Size matches the PDF. A finish-order race with eight or more placed riders and no sprint figures prints its rows in two columns, down the left and then the right, with the podium at the top of the left column and a header row over each column. The Bib column widens only for a race or standings group that has a four-digit bib, so such a bib prints whole. A name with letters the bundled font cannot draw, such as Chinese, Korean, or Arabic, is saved as typed: the red line under the field says those letters print as "?" on the PDF sheets, and the window, the board, and the CSV show them; a BikeReg import takes such a rider and says so in the row's Details. There is no fallback font. A Madison team's name is its row's first line, beside its color, with its riders under it. The results and standings sheets are Letter landscape and the program sheet portrait; the sheets are laid out for Letter paper only. A Madison team's riders print at the standings sheet's rider size under the team's name. A table that must split over a page and cannot give both pages four rows splits as evenly as it can. The results and the program share one header and one race heading: the band names the sheet (Results or Program) beside the date, written long, "Saturday, October 17, 2026" (the standings band spans its nights, "October 17 to 18, 2026"), the one exception to 2026-Oct-17, since the band is the sheet's title; every other date on a sheet, in a note, a column header, or the footer, is 2026-Oct-17, and the standings dialog's column header "Oct-17" is the short form of the sheet's "2026-Oct-17" (section 8a); each race starts with its number in the program in gray, its name, and its group, the results' state tag (FINAL filled, PROVISIONAL or IN PROGRESS outlined, as the window's tags are) or the program's count at the right, and gray lines saying how it runs; the footer says when it was generated. If a night's full date does not fit over its columns on the standings sheet, that table heads every night with the short form, "Oct-17", or with the month over the day when even that does not fit. The results stay in the data file; any past event can be opened and read.

## 10. The scoreboard

Dark background, white type, the venue's logo top left. Spectators may be a long way from the screen, so the test of every page is whether someone at the far end of the stands can read it: a full field of sixteen riders, the most a 166 m track may start (USAC 2B7), stands on one page with its names at the board's minimum, and fewer riders get larger type. A longer table turns pages that share the rows evenly, shown by page dots; a Madison table holds eight teams a page. Nothing on the board is smaller than about a thirtieth of the screen height, except the digits on a bib plate; a long name gives up its first name to an initial rather than shrink under that. The TVs are LCD panels that show every pixel, so the board keeps no safe area for overscan: one narrow margin at the sides of the top bar and the pages. Bold weights, high contrast, generous spacing; no small print, no footers, no legends, no explanation. Legible, simple, readable, and attractive, in that order.

- **Logo**: the logo and, under it, the event's name, large and in full white so the stands can read it. Shown at start and between sessions. The event's name is on this page only: a race page's header holds the race, its group and format, and the status, since the stands know where they are and the status reads better with the column to itself.
- **Start list**: the race's name and the field, shown the way the venue chose: names, bibs and names, or bibs only. The choice is for riders racing on their own: a team is always shown by its color and name, and on the start list with its riders' names. Up to six riders are one column of large names; a bigger field is two columns (24 riders fit), and a third opens only when two would set names under the minimum. A field of seven or more takes one column instead when that sets its names at least 3 percent larger than two half-width columns do, with rows as tall as theirs; at 1080p that is seven riders of a usual name length. The rows share the page as the race's table does: down to five rows' worth for riders and two for teams, split across the columns, and the names grow with them only while every name still fits whole and, for teams, every team keeps both riders beside its block. A grown rider list keeps room for a lap chip from the start, since a placed race shows its start list while it runs, so the first lap taken never steps it down; a list at its base sizes makes room for a chip as it always has, by setting its names smaller. A grown list's rows are never shorter than its base rows, so the plates keep their size. At 1080p five riders with names of a usual length are 93 px against 56, and two teams' riders 96 px against 45; a long name holds the growth back, and 24 riders keep the base sizes. A team list gives its blocks the spare room: a block takes 60 percent of its row when the riders' full names fit beside it, and only what the full names leave when they do not, so the color is as big as the list allows and a rider never gives up a name to it (the bars and names were small in an empty row).
- **Elimination**: the riders still in, large (as cards up to six, two cards across from four left, as two columns of rows above six, the last few filling the grid); the last rider the bell put out, larger, for a few seconds; the count of riders left below it; those the bell put out earlier, small. A rider who did not finish keeps their place in the result but is in neither list and is not counted as left.
- **Standings**: place, team or rider, SPRINT PTS (the sprint points so far, a plain number, blank until the rider scores; a bare SPRINTS heading read as a count of sprints), LAPS (the laps alone, "+1" or "−1"; the points they earn are the venue's known value and are in the total), a PENALTY column ("−5", in the loss color) only while a placed row on the board has one, TOTAL; every figure column is right-aligned, heading and figures to one padded edge, so a heading wider than its figures runs left over the heading row's empty middle and the columns stay as narrow as their figures (0.1.44); the leader's rank in the accent. No per-sprint columns: riders read the board at speed for their place, total, and laps, and the columns squeezed a long team name and made the table too busy; the one SPRINT PTS column lets the total reconcile on the board. A field of nine riders or more fills the page at the table's base sizes. A smaller field takes taller rows, sharing the page down to five rows' worth, and its type and figure columns grow together, but only as far as every rider's name still fits whole on one line, so a long name never gives up its first name to the larger figures, and the names keep their proportion to the totals rather than shrinking while the figures grow. The names are measured beside a PENALTY column whether or not one stands, so the first penalty given never steps the table down. At 1080p, with bibs and names, five riders with short names have totals of 101 px and names of 77 px, against 60 and 46 for nine riders and 44 and 36 for sixteen; a long name holds the growth back. The operator table keeps every sprint; the results sheet prints the points and laps. After Record Sprint, and when the final sprint completes, the sprint's result shows over the standings for 10 seconds, or until the next entry. The sprint's card is as wide as what it shows, centered on the board: each place, then the team block or the rider, the blocks at the widest team name, then the points one gap to the right, so each "+5" sits beside the team that earned it rather than at the far end of an empty row. The card is set larger than the table, up to half again, as far as the page's height allows; on a board narrower than 16:9, such as a window, a card of long names takes a smaller unit before it would run off the page's sides. Until a sprint or a lap counts, the start list stays up.
- **Team standings** (a Madison): place, team block, LAPS, a PENALTY column while one stands, TOTAL, and no riders' names and no SPRINT PTS column. Riders on the track read the board at speed for their team, place, and points, and asked for less; the total is what they race on, and LAPS says why a total jumped. The names are off the running page: at speed a team is its color, and the names are on the start list and the result, where there is time to read them. The block is the row from the place to the page's edge, one width for every team, and it carries the figures: LAPS, PENALTY while one stands, and TOTAL sit inside its right end, each under its heading. LAPS and PENALTY are in the block's ink. The total is near-black on a near-white plate edged in the gray of Black's ring, with the block's color showing evenly around it, so it reads the same on every color: a mid-tone such as Blue or Red gives its own ink only 4 to 4.5:1. A status row's word stays in the block's ink with no plate, so it reads apart from a scored row. A lap's green or red would vanish on a green or red block, so inside the block the sign alone says a lap was gained or lost. The team's name is centered on the block, or in the part left of the figures when the widest name would reach them. Once the officials decide the race, the places read "1st", "2nd", the winner alone in the accent, as on the result. The team's name is set at up to half the row's height, a little under the figures, never larger than the block holds, and never wider than the room left of the figures. The place and the total are the row's largest type, heavy, 62 percent of the row. The rows share the page whatever the field, so two teams fill it as five do, and a lone team takes half of it (riders at a practice Madison found the scores too small, and two teams used only the top of the page). At 1080p the figures are 260 px for two teams, 174 for three, 104 for five, and 65 for eight. LAPS and PENALTY grow with the row and stay under the total. The figures give way to the team names: when the widest name would not fit whole left of them, the figures, their plates, and the plates' margins shrink together, down to 84 px, before a name shrinks, since a team's name is what the stands match to the jerseys. Two teams with long names, or a 4:3 board, can show 84 px figures for that reason. The sizes are decided as though a lap and a penalty stood and the places were already worded as ordinals, so the first lap gained, the first penalty given, or the race being decided never steps the totals or the names down while the riders are reading them. Once the officials decide the race, a place column that would pass 14 percent of the page's width ("2nd" at a two-team row's height) sets its ordinals smaller than the total, so the team names keep their room. A page holds eight teams: USAC 2B7 allows twelve on a 166.66 m track, and twelve rows would set the names under the minimum, so a full field shows as two pages of six. No type on any board page is smaller than 36 px at 1080p (`theme.MIN_PX`). On a 65 inch TV that reads easily at about 8 ft and at the limit at 20 ft, so names are for the near stands; what a rider reads from the track is the team's color and the largest numerals. The team block is the team's color filled the row's height with the team's name set on it in near-black or white, whichever the color needs; Black keeps a light ring so it shows on the dark board; a long name shrinks inside its block rather than widening every row. Where riders sit beside a block (the start list), a team name has no initial to give up, so when a row is short of room the riders give way first: their first names go to initials, then the block shrinks toward its widest name at the floor, then they are left off. Only a team name too long for the whole row is cut. The block is how a team is drawn on every page: standings, the sprint result, the result, and the start list. The figure columns stay right-aligned, heading and figures to one edge, as every figure column on the board is: digits align by place value, so 9, 10, and 128 compare at a glance.
- **Result**: the first three large, the rest in two columns, or three when two do not fit (18 riders or more); every place shows up to 27. Provisional or Final. A small result (thirteen places or fewer at 1080p) shares the page as five places would at the least, and the podium and the places below it grow by one factor while every name fits whole, so the podium keeps its lead over the rest, and the places below the podium are never set shorter than at the base sizes. Only a decided result grows: a Win-and-Out shows its places here as the bells decide them, and sized by the places so far it would step down with every bell. At 1080p three places set their names at 112 px against 64, and six places at 98 and 58 against 64 and 38; sixteen places and more keep the base sizes. A points race (Points Race, Madison, Tempo Race) never comes to this page: its standings table stays up to the end and, once stamped Provisional or Final, reads as the result (the Team standings bullet). The table the stands watched during the race is the result they look for after it, and names and chips beside a block left the figures without headings to say which was which.
- **Between races**: the app sends no next-race page. An event opened with no race to select sends an empty page: the top bar with the logo, "Up next" over "Results", and nothing else. A data file closed for another sends the same page under the Logo face, so the TV shows the logo.

A rider marked Did Not Start, Did Not Finish, or Disqualified disappears from the board, except an Elimination DNF, who keeps the place USAC 2E4 gives and is listed there on the result page, with nothing beside the name. A withdrawn rider and a rider out of the finish (mishap) stay, since the rules still classify them (USAC 2O3(e), 1M6(d), 2M8(a)): the row keeps its points and laps on the running table and its place on the result, with nothing beside the name. The board never explains.

The preview under the program is the same canvas, fed the same calls, and it is the TV's one control (section 5): a click on it switches the TV between the logo and the race, under the pointer the picture dims under the monitor glyph and "Switch to Live" or "Switch to Logo" (the Off veil's shape, dark so the picture stays in color), and the Scoreboard menu's **Logo** and **Live** show and make the same choice. While the TV shows nothing, after None is picked in the Scoreboard menu or its display is disconnected, the preview is veiled, a click on it does nothing, and Logo and Live are grayed. Picking a display (or Automatic) is the one way back, and the board comes back to what was behind the veil, the race or the logo, since that grayed picture is what the preview promised. The menu is one list, no Display submenu and no Show Scoreboard switch: Automatic, each display with Full Screen or Windowed after its name (Windowed on the scoring window's own display, where the board can only be a window), then None.

## 11. Settings

Settings are the venue's: name, logo, scoreboard accent color, how the scoreboard names riders (Names Only, Bibs and Names, or Bibs Only; a venue whose announcers call riders by name picks names), backup folder, exports folder (where the three exports offer to save; Documents until one is chosen, and again while the chosen folder is missing), rulesets. They are set once. Save refuses a backup or exports folder that does not exist, since Choose... can only pick one that does. The accent color is the one color the scoreboard uses for emphasis (the leader, section labels, the latest sprint's card); a venue picks one of eight colors across the spectrum, each checked to read on the board's dark background, so the board draws it exactly as Settings shows it. There is no free color picker. There are no other scoreboard themes: the board is read from the stands, and one tuned look is the point. The logo is stored in the data file as the image itself (a PNG file only, scaled to fit 2880 by 1200 pixels when it is chosen; an image that declares a huge size is refused before it is decoded), not as a path to a file on one laptop, so the file carries everything the scoreboard and the exports need wherever it is opened. Which display the scoreboard uses, and whether it is up, are on the Scoreboard menu, because they are decided on the night.

A ruleset is one page: sprint points by place and whether there are double points for the last sprint, for the Points Race and the Madison; Tempo Race points per sprint; lap gained and lost points for each of the three; Elimination survivors; Win-and-Out places and direction; whether lapped Scratch Race riders are placed by laps down. The built-in **USAC 2025 + Club formats** holds the values from the USA Cycling Rulebook, version 8•25 (effective 2025-Aug-19), and the documented club values for the formats it has no article for. A venue copies it, changes the numbers, and sets its own as the default. A points table is typed as a comma-separated list, "10, 7, 5, 3, 2, 1", the one form a list of values takes in a text field, and the Multi-Race Standings **Place points** field is the same: the same values (whole numbers from 0 to 999), the same tooltip, and a refusal in the same words. Spaces, semicolons, or a sheet's hyphen run between the numbers ("10-7-5-3-2-1") are taken too; a hyphen with spaces around it ("10 - 7") is not, so a typed "-1" stays a negative that is refused. Inside a sentence on a sheet the table is the hyphen run of a race announcement, "10-7-5-3-2-1". The editor is a tab per scoring family (Scratch Race and Others, Points Race, Madison, Tempo Race, Elimination, Win-and-Out (Club)), each with that family's values, a **Fill USAC 2025 Values** button that puts the rulebook's numbers back on that tab (not on the Win-and-Out tab, whose values are a club's; each tab says whose values it holds), and, for each of the family's formats, what the venue calls it (**Shown as**) and one line about it (**Description**): two fields on a one-format tab, a table on the Scratch Race and Others tab, where an empty cell shows the rulebook's name in gray. Blank means the rulebook's name and no line. The name is the format's name everywhere a race made from the ruleset appears: the race's default name, the program, the scorer's header, the scoreboard, and the results sheet. The description shows once, under the scorer's header, and nowhere else. A race keeps the words it was made with along with its rules. Renaming a ruleset renames it on its races. Import from File... takes a ruleset file only when the editor could hold every value in it. A value out of a box's range, a sprint point over 999, or a points table of more than 50 values is refused on the red line by name and range, before anything is stored. A file that can't be read says why in plain words and keeps the file's name as spelled. Deleting one leaves its races their rules and its name, which the program and the race dialog show as "Club X (deleted)"; the results sheet prints the name alone.

## 12. Data

One file per venue, for as long as the venue runs races; there is no new file per season. Riders, series, and every past result stay together, and a decade of nights is a few megabytes. The file is chosen or created from the File menu; the last file used opens at the next start, with the race that was live selected. A new file (a second venue, a practice file) made while one is open offers to copy that file's settings, logo, rulesets, and riders, and never its events: the open file is the template, and there is no other kind. Every entry is one appended row, written and confirmed before the screen says so; a result is always computed from the rows, never stored as a number that could drift. A backup of the whole file is taken when a race becomes provisional, when it is marked final, on close, and on request; it goes beside the file, where the newest twenty are kept, plus the last backup of each of the last ten dates (the date the backup was taken, from its mark), and the close copy also goes to a second folder such as a USB stick if the venue sets one, which is never pruned. Backup Now asks where to save its copy, starting in that folder. A copy cut short by a crash or a forced quit leaves a partial file in the automatic folder, and the next backup clears it. Restoring is opening the backup. A restore over an existing data file first copies what that file holds into its backups folder as a before-restore copy, which rotation never deletes.

Help > Demo Data File... asks Open Previous or Create New (the question says what a new one holds, that the next start returns to the venue's file, and where the demo is stored; Open Previous is grayed with no demo on disk or while it is open), and Create New builds a sample data file and opens it: invented riders, two events (one scored and final, one with a race of every format to score), and a demo ruleset. It is for a new scorer, or anyone who downloaded the program, to see how it works without making one of each race first. The demo is its own data file, demo.sqlite, in a "demo" folder under the folder the program started with (the per-user data folder, unless a data folder was given), and it is built fresh, replacing the last one, each time it is chosen. It has its own name so a look at the folder never shows two madtracker.sqlite files. Scoring in it is saved as in any file, its automatic backups go to its own backups folder, and its Settings has no second backup folder, so nothing of it reaches the venue's file, backups, or stick. It is open for the session only: the program never remembers it, so the next start returns to the venue's file, and File > Open Data File goes back sooner. The demo file stays on disk and can be opened by hand.

### Removing riders

A result is history, and nothing a scorer does later changes it.

- Removing a rider from an event's roster removes that event's entry only. It is allowed while the rider is in no race of the event, or only in races not yet scored, from which they are then dropped. A race undone to its start list is not yet scored (section 6). Once the rider is in a scored race it is refused, with the reason. Other events are untouched.
- An event is deleted from Open Event while none of its races has ever had an entry: its program, fields, teams, and roster go, and its riders stay in Edit Riders. An event with a race that has ever had an entry (even one whose entries were all undone, since the log keeps them) is never deleted, and "Has raced" shows under Delete. Test scoring belongs in a practice data file.
- A rider who has raced (is in the field of a race that has any entry, undone or not) is never deleted, and stays in the list for good. A rider taken out of the field of a race undone to its start list has not raced in it. When Delete is off, "Has raced" shows under it. Any other rider can be deleted. The confirmation names the rosters they come off, and they leave those rosters and any race fields with them.
- Editing a rider (a corrected name, a new USAC License) applies everywhere, past events included: the name is the person, not the result. PDFs and CSVs already written are files and do not change.
- One person entered twice is joined with Merge With..., in File > Edit Riders. It starts from either record and asks two questions, one page each, with nothing answered for the scorer. Merge Riders first lists every other rider, likely matches first with the reason in a Match column, and nothing selected. The second page settles the merged record one line per value, as JOSM settles two ways' tags: first name, last name, USAC License, UCI ID, birth year, then a bib, group, or Madison team for each event or race where both records have a different one, then the events either is in. A value both give, or only one gives, is shown and kept. A value that differs is tinted with a Choose... list holding both, and Merge is off until each is chosen; a gray count beside the buttons says how many are left. A rider value neither record has (a USAC License, UCI ID, or birth year) is a gray cell to type in, checked as Edit Rider checks it, so a merge tidies the record in one pass. There is no confirmation, since every value lost was chosen on the page. Which database row survives is not the scorer's question: the one that has raced, since its race logs name it, or else the one started from, and it takes the chosen values. The spare's roster entries and its places in races not yet scored move to it, and the spare is deleted. A team not chosen is left a rider short, fixed in Edit Race. Two records that have both raced stay two: starting from a raced record, the other raced records are off on the first page.
- The venue's list is kept in File > Edit Riders only: New Rider, Import from BikeReg, Edit, Merge With, and Delete are there and nowhere else. Edit Riders needs no event open and has no roster boxes. Choose Riders only picks from it.

## 13. Acceptance
