# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Scoring software for track cycling racing, built for a venue in Detroit and meant to be usable by any venue that runs track races. A human scorer enters placings, sprint results, eliminations, and lap gains as a race runs; the app computes standings, drives a full-screen audience scoreboard on a second display, and produces archival PDF results and the USAC results CSV. No timing hardware, no network at runtime. Windows, macOS, and Linux are all first-class targets; Linux is where it is developed and tested headless.

Display name "MadTracker" lives in one constant, `madtracker.APP_NAME`. Version 1.0.0 is released (`madtracker.__version__`); later releases follow the routine at the end of `docs/releasing.md`, and every change after 1.0.0 bumps the patch. A feature release (1.x.0) is built on a branch as candidates (1.1.0rc1, rc2, and so on, one bump per commit) and merged to `main` with a merge commit on the maintainer's go. `docs/changelog.md` holds the version-by-version record. Plans, mockups, and dated reports live under `.claude/plans/` (gitignored, kept by the maintainer; its `backlog.md` lists what is open). The maintainer builds and tests each candidate on Windows and macOS. The design is `docs/design.md`; when code and document disagree, the code is wrong. Timed events are on hold (`.claude/plans/timed-events.md`), a stream overlay is researched and not built (`stream-overlay.md`), and a venue track length is a maybe for after 1.0 (`track-length-2b7.md`).

## Settled rules not stated elsewhere here

- Every dialog and ⋯ menu goes through `widgets.run_dialog` or `widgets.exec_menu`, which delete it after it closes; a bare `exec()` is never written. There is no `QInputDialog` (the icons test forbids it): names are asked with `widgets.NameDialog`.
- The USAC CSV's ten columns match USAC's own template character for character (`local/scorer-files/2024 Results template.csv`, `docs/research/usac-results-export.md`); no CSV output changes without the maintainer's OK.
- A name the PDF font cannot draw is said while typed (`widgets.note_unprintable`), never refused; there is no fallback font.
- The harnesses' generators write only what the window offers: a path the app already prevents is not tested or fixed (check the menus, the controller's refusal, and Undo's order before calling a finding a defect).
- The 90 s `faulthandler_timeout` is the hang guard and is never raised to hide a slow test; a slow test is profiled and its cost cut (the fuzz garbage test is the one agreed exception).
- Undo's depth is uncapped, and the result backup runs on the GUI thread.
- Wording: points are "awarded", never "paid"; the book is "USA Cycling Rulebook" everywhere (`RULEBOOK_TITLE`); a PDF is exported, never "printed" or "previewed". Scorer-facing wording is shown to the maintainer before it is built.
- A team is its riders: `Store.save_race` keeps a renamed or recolored team's id and its staged clicks, and only a change of riders makes another team.
- `board_feed` keeps a status row off every running board, so the pages' status-row rules are defensive only.
- The board pages are sized so nothing steps down mid-race: each page's sizes are decided as though the later items stood (a lap, a penalty, ordinals), and grown rows are never shorter than the base.
- Every PDF keeps 10 mm clear of each edge, the band included (`tests/export/test_page.py`), so the PDF is the page a printer gives back.

## Commands

Run from the repo root with the venv active (`source .venv/bin/activate`; the venv is `.venv/`, Python 3.14 here, floor 3.12).

```bash
# Run the app (real store under the per-user data dir)
python -m madtracker
python -m madtracker --demo                # a seeded demo event in a temp dir
python -m madtracker --data-dir /some/dir  # another data dir
python -m madtracker --mockup DIR          # render both windows to PNGs, headless, and exit
python -m madtracker --self-test           # store + exports smoke test, exit code is the result
python tools/doc_screenshots.py            # README screenshots from the demo event, footnoted with the version; only when the maintainer asks

# Tests and lint; both must pass before committing
QT_QPA_PLATFORM=offscreen pytest -q        # offline, about two minutes; conftest sets offscreen anyway; any warning fails (pyproject filterwarnings)
pytest -q tests/ui/test_app.py -k "riders"  # one file, or one test by name
QT_QPA_PLATFORM=offscreen pytest -q -m fuzz  # the input fuzzer's deep tier (minutes); FUZZ_SEEDS=10 widens it
ruff check madtracker/ tests/ tools/
ruff format --check madtracker/ tests/ tools/

# Packaged builds, each on its own OS (see docs/building.md); each makes its
# own build venv from requirements.txt, runs the suite, PyInstaller, then the
# built program's --self-test. Add -SkipTests / --skip-tests to go straight to the build.
powershell -ExecutionPolicy Bypass -File packaging\build_windows.ps1
packaging/build_macos.sh
packaging/build_linux.sh
```

Mockups for the maintainer go to `.claude/plans/mockups/` (gitignored). Tests never need a display or the network.

## Architecture

- **`madtracker/scoring/`** is pure: `compute_for_format(format_key, rules, entrants, actions) -> Standings` and `validate_for_format(...)`. Actions (`actions.py`) are frozen dataclasses with a `kind`, a `SCHEMA_VER`, and a JSON payload; rules (`rules.py`) are dataclasses built from the one Rulebook or a venue's stored ruleset; engines are `placings`, `elimination`, `sprint_points` (points, madison, tempo), `win_and_out` (a club format), and `aggregate`; `control/formats.py` is the one table of offered formats, USAC article or club source. Every rule cites its article and has a named test; `tests/scoring/test_golden_night98.py` reproduces a venue's real sheets. Change a rule here only with its test.
- **`madtracker/store/`** is SQLite: WAL plus `synchronous=FULL`, explicit short transactions, migrations keyed by `user_version`. `race_action` is append-only (triggers refuse UPDATE and DELETE); undo is a `void` row. `Store.live_actions(race_id)` is what scoring replays. Backups go through the backup API only. The data dir comes from `paths.py` (never next to the exe, never a synced folder). SQLite reuses a deleted row's id (no AUTOINCREMENT), so anything keyed by a rider or team id outside the log, such as the staged clicks in the setting table, is cleared when that row is deleted or replaced. The schema is one baseline entry in `store/migrations.py` that creates every table in one step at version 4 (a file numbered below it is refused), plus one new entry per later change; a later change also commits a version 4 fixture file and a migration test with it.
- **`madtracker/control/`** ties them together. `race.py` is `LiveRace`, the controller behind the scoring surface and the review: `task()`, `click()`, `rider_actions()`/`act()`, `record_sprint()`, `review_actions()`/`review()`, `reopen_sprint()`, `mark_final()`/`reopen()`, `undo_text()`/`undo()`, `screen()`; everything that changes a race goes through one `_record` path that validates against the log as it would stand, appends, and moves the race state; the staged order (clicks not yet an entry) is written to the setting table on every click. `describe.py` puts actions into words for the logbook and Undo (`who()` writes a bib as `#12`). `formats.py` is the one table of offered formats (key, label, USAC article or club source); every picker and label derives from it. `riders.py` finds likely duplicates for the import preview and merges a spare rider record. `copying.py` copies settings, logo, rulesets, and riders into a new file and a program into a new event. `roster.py` is the field and team view of a race, and the one place a bib is checked: a bib is required to score, never to register, and must be unique within a race's field, not the event; every path that builds a field refuses a clash or a missing bib there, and such a race shows the refusal as its task line. `board_feed.py` turns Standings into scoreboard payloads. `rulesets.py` holds rulesets: one built-in ruleset, USAC 2025, named from the edition constant in scoring/rules.py (USAC and UCI score identically), venue sets as one page of values in the `ruleset` table; house rules are never in code; no track length, lap counts, or intervals anywhere, a race asks only for its sprint count or places. `venue.py` is the venue settings (name, logo bytes, rider label, accent color, backup folder). `backups.py` always writes the automatic folder and treats a chosen folder as an extra copy. Entrant ids are rider ids for individual races and team ids for madisons.
- **`madtracker/ui/`** is the operator window built to the design: `window.py` (program and preview left, surface middle, the Edit | Score and Undo bar along the bottom; File, Scoreboard, and Help menus; F1), `program.py`, `surface.py` and `cards.py` (the task line and the rider cards), `review.py` (the result list), `tv.py` (the scoreboard preview, its Off and hover veils), `setup/` (a package: the Edit Event screen in `screen.py` and its dialogs in `events.py`, `riders.py`, `importing.py` for the BikeReg import, `race.py`, and `groups.py`, with `__init__.py` re-exporting every name the app and tests reach; the dialogs call `icons.ask` through the module, so a test patches `icons.ask`), `help.py` (the scorer's help pages in `madtracker/help/`, kept apart from `docs/`: Getting Started, Scoring, Results, Multi-Race Standings, Backups; `docs/installing.md` stays in the repo, not in the help; the Markdown is restyled after Qt renders it, the contents list shows the open page's sections, and F1 opens the section for the screen in view via `HELP_HERE`), `settings.py`, `rulesets.py`, `widgets.py` and `style.py` (one spacing scale, font-derived control heights, one button order on every platform, flat sheet), `look.py` (Fusion with a fixed light palette; registers the bundled Inter), `icons.py` (Material Design Icons tinted from bundled SVGs; every dialog goes through its helpers, and a test fails on any stock QMessageBox or StandardPixmap; `ask()` makes Cancel the default button on every question), `about.py` (the About dialog: credits with runtime versions and the bundled license texts under `assets/licenses/`; a test fails when a dependency in `pyproject.toml` is not credited). **`madtracker/board/`** is the scoreboard canvas and its pages; it is driven by payloads, never by the store directly, and the same canvas is the preview; `wordmark.py` draws the default logo as vector at paint time, and every pixmap the board draws is scaled in physical pixels for the display's device pixel ratio. Type in the window is sized only through `look.text_scale()` (`style.ui_font`, the style sheet, `dialog_point_size`), so it is the same in pixels on every platform. A label shows data as plain text; one that means to be rich sets `Qt.TextFormat.RichText` itself, and any name put into HTML goes through `html.escape`. A field whose text prints on a PDF sheet (a rider, team, race, group, event, series, venue, or standings name) calls `widgets.note_unprintable` with its red line. **`madtracker/app.py`** wires windows, displays, and the store; keep it thin.
- **`madtracker/importers/bikereg.py`** parses the BikeReg entries export and plans an import (match by license, then UCI id, then unambiguous name) before applying it.
- **`madtracker/export/`** writes the USAC CSV and the PDF/A-2B results sheet from one shared row builder (`summary.py`), so the two never disagree.
- **`madtracker/assets/`** holds the app icon (MDI bike), the placeholder wordmark that is the default scoreboard logo, and the bundled Inter typeface (`fonts/`, OFL) used by the window, the board, and the PDF. The app ships no venue trademark; the venue's wordmark lives in `local/` (gitignored) and is chosen in Settings. The public history starts at one squashed commit; the earlier history holds the venue's wordmark, is kept in a local clone outside the repo, and is never pushed.
- **`packaging/`** builds all three platforms from one PyInstaller spec: Inno Setup per-user installer plus portable zip on Windows, `.app` in a DMG on macOS, tarball on Linux; `.github/workflows/` runs the suite on all three and `release.yml` builds on a `v*` tag. Before tagging a version, run the fuzz tier (`pytest -m fuzz`, see Commands). Each build script runs the suite (unless told to skip it), PyInstaller, and the built program's `--self-test`; the maintainer builds and tests the Windows and macOS packages on their own machines, and `release.yml` builds all three in CI. `tests/test_package.py` checks every file under `madtracker/assets/` against the spec's data globs, because a file read through `importlib.resources` that the spec omits fails only in the frozen app.

## Hard constraints

- Windows 10/11, macOS, and Linux are all first-class targets: same screens, keys, and behavior; packaged for each; machines of each kind are available for testing and building. Offline. SQLite storage in one file that can be copied to another laptop and opened there.
- Every scorer action is committed before the UI acknowledges it. Nothing ever edits or deletes a `race_action` row.
- Outputs: PDF results per event (archival), USAC results CSV. Never round-trip the CSV through Excel.
- Comments carry design rationale (why), not narration (what), stated as a present-tense constraint ("the strip is the row's full height so it takes a finger"); no history in code or docs: no dates, names, version numbers, or descriptions of earlier behavior (the changelog and git hold those); rulebook citations stay; docs are plain language (one fact per sentence, active voice, conditions before actions, exact terms kept); American English; no em dashes anywhere, including commits and chat; no emoji; never the word "spike".
- Check the license of every dependency before adding it and credit it in the README credits table and the About box.
- Tests must run offline, in seconds, on Linux, Windows, and macOS. Run the suite with output to a file, never through a pipe: a dialog raised during teardown would otherwise hang silently (`QT_QPA_PLATFORM=offscreen timeout -s KILL 400 pytest -q -p no:cacheprovider -o faulthandler_timeout=90 > log 2>&1`). `tests/ui/test_design_walk.py` is the acceptance walk: a table of every control in every state per format, plus a sweep that clicks every visible control and fails on silence; new scorer-facing behavior gets a row there. A test that builds an `AppController` lets it go with `tests/apps.py` `dispose_app`, never `close()` alone: a closed controller keeps its windows, and the suite's memory grows by several gigabytes. macOS caps a process at 256 open files, so a test that builds many `AppController`s disposes each before the next. Run one full suite, fuzz tier, or build at a time, under a memory cap where one is set up (`.claude/tools/run.sh`), and at most three agents at once.
- Never put real rider names or license numbers in code, tests, or docs. The venue's files (the scorer's workbooks, wordmark, house ruleset, research) live in `local/` (gitignored, see `local/README.md`); invent names.
- Commit on `main` as work progresses: atomic commits at logical points, without waiting to be asked. Every commit that changes the app bumps the version (`madtracker/__init__.py` and `pyproject.toml`) in that same commit, so builds can be told apart while testing: the patch number (1.0.1, 1.0.2, and so on). A commit that changes only docs, tests, tools, or CI does not bump it. Push `main` to `origin` after committing; `ci` runs the suite on all three platforms on every push, and a `v*` tag runs `release`. New test features or new testing approaches need the maintainer's OK before they are committed. Run every git command as `git -C <repo root>`.
- Settings is for the database: venue values that are set once and almost never changed (venue name, logo, rider label, accent color, backup folder, default ruleset). Anything changed during a night or specific to the machine (the scoreboard display, Logo/Live, show or hide the board) lives on the Scoreboard menu, and nowhere else. One place per setting.
- A row or item is selectable only when selecting it does something; otherwise the table takes no selection and no focus, and uses alternating row shading for scanning. Menu items carry no icons (Qt draws them in the check-mark slot). There is no status bar: a failure the scorer must know about (a failed backup, a lost display, a slow disk once per session) is a message box through `MainWindow.report_failure`, a refusal that answers a click is the surface's red line, and routine activity shows nothing.
- Capitalization follows Apple's macOS guidelines: title style (every word capitalized except articles, coordinating conjunctions, and prepositions of four or fewer letters, unless first or last) for window, message-box, and file-dialog titles, buttons, menu titles and items (including the ⋯ menus), tab titles, column headers, pane and group-box headings, and app-defined list items; sentence style for checkboxes, radio buttons, form labels, tooltips, placeholders, status and refusal lines, the task line, and message bodies. The Undo label is "Undo:" in bold, then what was done in plain weight as a sentence in the past tense, verbs lowercase, UI names (a status, "Sprint 3") and the names in it as spelled ("Undo: #7 Maya Petrakis lost a lap", "Undo: Silver placed 4th", "Undo: #12 Tess Gallagher marked Did Not Finish"; what was done, never "clicked"); "Nothing to Undo" and "Reopen First to Undo" stay title style. The scoreboard, the PDF and CSV, logbook text, and user and data values (event, rider, group, format, ruleset names) keep their own words. Help and docs name controls exactly as the UI spells them.
- Do not over-explain in the UI: make it obvious through established design practice and standards. No legend footers, no paragraphs of hints, no columns that are usually empty. A control's label and placement say what it does; details go in a tooltip; a refusal explains itself in the red line once. Errors and confirmations stay; explanations of the design do not.
- Visual detail is a requirement, not polish for later: text centered in its control, explicit control heights and one spacing scale rather than platform defaults, the same look on Windows, macOS, and Linux, and Qt's per-platform conventions (button order, dialog look) overridden where usability, cross-platform consistency, or modern styling is better served. Check mockups for alignment before reporting.
- Do not use preview or screenshot tools without asking. Rendering the app's own windows headless with `--mockup` is fine.
- Subagent packages: one package per commit, each in its own git worktree; the lead session reviews the diff and the mockups and reruns the checks before committing; agents never commit and never run `ruff format` outside their own files. The venv's editable install points at the main tree, so an agent in a worktree runs Python and pytest with `PYTHONPATH=<worktree>` or it tests the wrong code.
- A deferred single shot names its widget as the context (`QTimer.singleShot(0, self, slot)`), so it never runs after the widget is deleted. Qt on Windows: never switch the application style once widgets exist (`apply_look` runs once at startup, and the test session applies it once in `tests/conftest.py`), and never reassert geometry from an event handler against the style sheet; both re-polish every live widget and hung the suite there. Give a widget's own style rule the value instead (`QPushButton#rider { min-height: 0 }`).
- Race formats: a format is offered when the USAC rulebook has an article for it, or, as a club format, when a named venue's public page describes it, cited with a link that resolves; nothing is invented, and the Scoring help page (`madtracker/help/scoring.md`) says where each comes from and how it is scored.

## Domain vocabulary

The design is `docs/design.md`; its section 3 is the vocabulary, one word per idea, used the same way on screen, in code, and in docs. In short: **Venue** (one data file), **Series** (optional grouping of events), **Event** (one date of racing, with a roster and a program), **Roster** (riders entered with bibs), **Rider**, **Group** (a label on a roster entry), **Program** (the races in order), **Race**, **Field**, **Team**, **Format**, **Ruleset**, **Result**. "Track cycling", not "velodrome"; "venue", not "facility"; "event", not "meet". The scorer operates the app; officials call placings.

## Ground level

The schema baseline is the whole history, and nothing in code or docs refers to older files, previous versions, or legacy names.
